# AF-MilitaryShogi（軍人将棋）

人間 vs CPU の31枚型軍人将棋（Unity 3D / Windows）。検証テーマは「不完全情報から推論し、状況に応じて意思決定するCPU」。CPUが**何を知り、何を推測し、なぜその手を選んだか**を思考モニターで観察できる。

- 起動：`bin/Release-<Version>/AF-MilitaryShogi.exe`（ビルド手順は下記）
- 作業規約：[AGENTS.md](AGENTS.md)／変更履歴：[HISTORY.md](HISTORY.md)

## 採用ルール（固定・ローカルルール切り替えなし）

盤・勝敗表は「8列31枚編成X字型」の古典的な盤（一ノ瀬武志『軍人将棋ルール研究』）と、足立将棋センター配布の勝敗表に基づく。解釈が分かれる点は 2026-09-23 にユーザーへ確認して決定した（★印）。

- **盤**：各陣地8列×4行。両陣地の間に帯があり、通常の駒は2つのX字突入口を通らないと越えられない。左の突入口は各陣最前列の1・3列目、右は6・8列目（左右対称）とつながる。各Xの中心が**中央丸**。盤は `BoardGraph`（66ノードのグラフ）で表す。
- ★**中央丸**：通常のマスとして扱う（1駒が滞在でき、戦闘も可）。アーム端⇔中央丸⇔自陣・敵陣どちらのアーム端も1手。
- **総司令部**：各陣地の最後列中央2マス。**大将・中将・少将・大佐・中佐・少佐**がどちらかのマスを占領すると勝ち。他の駒は入れるが勝ちにならない。
- **駒構成**：大将1・中将1・少将2・大佐2・中佐2・少佐2・大尉2・中尉2・少尉2・飛行機2・タンク3・騎兵2・工兵3・スパイ1・地雷3・軍旗1（31枚、1マス空き）。
- **移動**：将校・スパイは前後左右1マス。タンク・騎兵は前後左右1マスまたは前へ2マス（飛び越し不可）。工兵は前後左右に何マスでも（飛び越し不可）。飛行機は縦に何マスでも（飛び越し可、帯を突入口なしで越えられる、中央丸には止まらない）・横1マス。地雷・軍旗は動かない。
- ★**多段移動と中央丸**：タンク・騎兵の前2マスや工兵の移動は中央丸に入ったところで止まり、中央丸から出る移動は1マスのみ。
- **勝敗表**：攻撃・防御に依存しない（スパイは攻めても守っても大将に勝つ）。同種は相打ち（両方除去）。地雷は飛行機・工兵に負け、他とは相打ち。詳細は `CombatTable`。
- ★**軍旗**：戦闘の時点で同じ列の1つ後ろ（自陣奥側）にいる味方駒と同じ強さ。空・敵駒なら全ての駒に負ける。軍旗が負けても後ろの駒は除去しない。
- **初期配置**：自陣内に自由配置。地雷・軍旗は突入口（アーム端4マス）不可、軍旗は最後列不可。★地雷は総司令部に置ける。
- **その他**：手番の駒が1つも動かせなければ負け。総手数800、または戦闘なし160手で引き分け。先手は人間（手前＝South）。
- **情報**：撃破した敵駒も含め、敵駒の正体は終局後も公開しない。公開されるのは敵駒の番号・位置・移動（経路と飛び越し枚数）・戦闘の事実と結果（勝ち・負け・相打ち）だけ。

## 情報隠蔽の構造

```
MilitaryShogi.Rules        公開ルール（駒種の列挙、盤グラフ、移動規則、勝敗表、配置思想）
MilitaryShogi.Observation  観測データ（PlayerView）。敵駒 EnemyPieceView には駒種のフィールドが存在しない
MilitaryShogi.Engine       AuthoritativeGameState（internal）＋ Judge ＋ ObservationBuilder。Match だけが公開
MilitaryShogi.Cpu          CpuKnowledge / CpuBrain。参照は Rules と Observation のみ（Engine を参照しない）
MilitaryShogi.Game         Unity表示。人間側の画面も人間の PlayerView だけで描く
```

- 真の駒種は `Engine` の internal な `AuthoritativeGameState` にだけ存在する。`Match` の公開APIで駒種を返すのは終局後限定の `RevealAfterGameEnd`（テスト用）だけ。
- CPUのアセンブリ（Unityのasmdefとテスト用csproj）はEngineを参照しないため、敵駒の真の種類を扱うコードはコンパイルできない。
- 駒のID・番号は初期位置の順に振るので、IDから駒種は分からない。
- 敵駒の表示オブジェクトは裏面テクスチャだけで生成され、駒種を受け取らない。戦闘演出（接近・衝突の光輪・揺れ・消滅）は全駒共通で、違いは公開情報である勝ち・負け・相打ちの表示だけ。

検証（`Run-Tests.ps1` の Boundary 系）：CPUアセンブリの参照、asmdefの参照、観測型に駒種フィールドがないこと、CPUソースにリフレクション等がないこと、そして**敵の駒種だけを入れ替えた2つの対局でCPUの判断（候補・評価値・確率）がビット単位で一致すること**を確認する。

## CPUの思考方式

**1. 知識（CpuKnowledge）**：敵駒31枚それぞれについて16種の候補と確率を持つ。
- **ハード制約**（候補の除外）：観測した移動を、その駒種が本当の移動規則でできたかを移動前の盤面（公開の占有状況）で検査して除外する。1マスでも動けば地雷・軍旗を除外、3マス直進なら工兵・飛行機、横に長く動けば工兵、駒を飛び越えたり突入口を通らず帯を越えたりすれば飛行機に確定。戦闘結果は勝敗表と自軍の駒種から整合しない種類を除外する（自軍の軍旗は後ろの駒の強さで、敵の軍旗候補は後ろの敵駒の候補で判定）。初期位置による配置ルール（突入口に地雷・軍旗なし、最後列に軍旗なし）も使う。
- **ソフト証拠**（弱い重み）：初期位置の一般的な傾向、自ら攻撃してきた駒は強い駒寄り、司令部へ接近する駒は佐官以上寄り。
- **枚数制約**：31枚が標準構成であることを、（駒×種類）行列の反復比例フィッティングで満たし、各駒の周辺確率を得る。飛行機が1枚確定すれば他の駒の飛行機確率が自動的に下がる。
- 変化は駒ごとに「Turn n: 理由 ⇒ 更新後の上位候補」として記録し、直接の証拠がない駒の確率が他の駒の判明で大きく動いた場合も「再配分」として記録する。

**2. 意思決定（CpuBrain）**：全合法手について、戦闘なら勝ち・負け・相打ちの確率（信念×勝敗表）で分岐した局面を作り、静的評価の変化量で採点する。
- 評価項目：駒得（敵の価値は信念の期待値）、前進（大将〜少佐の敵司令部への接近）、司令部防衛（佐官以上らしい敵駒の、自駒の強さを考慮した経路長による危険度、迎撃できる自駒の近さ、次の手で占領される確率）、被攻撃リスク、攻撃機会、情報価値（安い駒で不確かな敵駒を突く期待エントロピー減少）、反復抑制。
- **2手読み**：全候補について相手の応手を読む。相手は自分の駒種を知っているので、敵駒ごと・移動クラスごとに信念で重み付けした応手を評価し、最も痛い応手を重み0.7で織り込む（司令部占領は負けとして扱う）。
- 評価が僅差（0.15以内）の手は Decision Seed の乱数で選ぶ。配置思想ごとに前進・防衛・リスク回避などの重みを少し変える。

**3. 配置思想（FormationGenerator）**：いのちだいじに／ガンガン行こうぜ！／じっくりいこうぜ／わなにはめろ／きどうせんだ！。駒種ごとの好む深さ・突入口への寄り・司令部への寄り（と軍旗の後ろに置く駒）を思想ごとに定め、Formation Seed のガウスノイズで揺らぎを加える。通常は Formation Seed から思想を決め、設定画面で明示指定もできる。

## Seed

| Seed | 用途 |
|---|---|
| Player Formation Seed | 人間の「おまかせ配置」（思想もこのSeedから決定） |
| CPU Formation Seed | CPUの配置思想（自動時）と初期配置 |
| CPU Decision Seed | CPUの僅差の手の選択（手番ごとに派生） |

乱数は `DeterministicRandom`（SplitMix64）で、Unity と .NET テストで同じ系列になる。同じSeed・同じ手順なら同じ配置・同じ判断を再現する。CPU配置を固定してDecision Seedだけを変えると、同じ初期局面から異なる判断を比較できる。

## 操作

- 初期配置：自軍の駒をクリック → 青く表示されたマスをクリックで移動・交換。「おまかせ配置」でPlayer Seedから再配置。Seed欄は「適用」「乱数」。
- 対局：自軍の駒をクリック → 緑（移動）・赤（攻撃）のマスをクリック。右クリックで選択解除。
- 敵駒にマウスを合わせると、その駒について観測した移動・戦闘の履歴を表示。
- M：思考モニター（研究用、別パネル）／H：戦闘履歴／F：演出ON/OFF／N：番号表示。上部バーで演出速度（×1・×2・×4）。
- 思考モニター：意思決定タブ（Seed・配置思想・採用手・採用理由・候補手と評価の内訳・想定応手）と敵駒の推定タブ（各駒の16種の確率、除外、推定の根拠と変化）。◀▶で過去の手番の判断を表示。「CPU駒の正体を表示」は既定でOFF（ONでCPU自身の駒種を表示）。推定タブでは比較のため、あなた自身の駒の実際の種類を併記できる。

## ビルドとテスト

```powershell
./Run-Tests.ps1            # 全テスト（約4分）。-Quick で短縮
./Build-Windows.ps1        # bin/Release-<Version>/AF-MilitaryShogi.exe
./Run-AutoTest.ps1         # ビルドしたEXEで自動対局して検証、Builds/AutoTest/<日時>/ に結果
```

- `Tests/` の .NET 9 プロジェクトは `Assets/Scripts/{Rules,Observation,Engine,Cpu}` をUnityのasmdefと同じ参照関係でコンパイルする。
- EXEの自動検証（`-autotest`）：全66ノードのマウス選択の逆変換、クリックによる配置編集（禁止配置の拒否・交換）、人間側の着手をクリック処理経由で行って終局まで進行、毎フレーム全ての敵駒のマテリアルが裏面テクスチャのみであることを検査、スクリーンショット保存。

# AF-MilitaryShogi（軍人将棋）

人間 vs CPU の31枚型軍人将棋（Unity 3D / Windows）。検証テーマは「不完全情報から推論し、状況に応じて意思決定するCPU」。CPUが**何を知り、何を推測し、なぜその手を選んだか**を思考モニターで観察できる。

- 起動：`bin/Release-<Version>/AF-MilitaryShogi.exe`（ビルド手順は下記）
- 作業規約：[AGENTS.md](AGENTS.md)／変更履歴：[HISTORY.md](HISTORY.md)

## 採用ルール（固定・ローカルルール切り替えなし）

盤・勝敗表は「8列31枚編成X字型」の古典的な盤（一ノ瀬武志『軍人将棋ルール研究』）と、足立区生涯学習センターのサイトで配布されている勝敗表（https://www.adachi-shogakucenter.net/download/gunzin.pdf ）に基づく。解釈が分かれる点は 2026-09-23 にユーザーへ確認して決定した（★印）。

- **盤**：各陣地8列×4行。両陣地の間に帯があり、通常の駒は2つのX字突入口を通らないと越えられない。左の突入口は各陣最前列の1・3列目、右は6・8列目（左右対称）とつながる。各Xの中心が**中央丸**。盤は `BoardGraph`（66ノードのグラフ）で表す。
- ★**中央丸**：通常のマスとして扱う（1駒が滞在でき、戦闘も可）。アーム端⇔中央丸⇔自陣・敵陣どちらのアーム端も1手。
- **総司令部**：各陣地の最後列中央2マス。**大将・中将・少将・大佐・中佐・少佐**がどちらかのマスを占領すると勝ち。他の駒は入れるが勝ちにならない。
- **駒構成**：大将1・中将1・少将2・大佐2・中佐2・少佐2・大尉2・中尉2・少尉2・飛行機2・タンク3・騎兵2・工兵3・スパイ1・地雷3・軍旗1（31枚、1マス空き）。
- **移動**：将校・スパイは前後左右1マス。タンク・騎兵は前後左右1マスまたは前へ2マス（飛び越し不可）。工兵は前後左右に何マスでも（飛び越し不可）。飛行機は縦に何マスでも（飛び越し可、帯を突入口なしで越えられる、中央丸には止まらない）・横1マス。地雷・軍旗は動かない。
- ★**多段移動と中央丸**：タンク・騎兵の前2マスや工兵の移動は中央丸に入ったところで止まり、中央丸から出る移動は1マスのみ。
- **勝敗表**：攻撃・防御に依存しない（スパイは攻めても守っても大将に勝つ）。同種は相打ち（両方除去）。地雷は飛行機・工兵に負け、他とは相打ち。詳細は `CombatTable`。
- ★**軍旗**：戦闘の時点で同じ列の1つ後ろ（自陣奥側）にいる味方駒と同じ強さ。空・敵駒なら全ての駒に負ける。軍旗が負けても後ろの駒は除去しない。
- **初期配置**：自陣内に自由配置。地雷・軍旗は突入口（アーム端4マス）不可、軍旗は最後列不可。★地雷は総司令部に置ける。
- **その他**：手番の駒が1つも動かせなければ負け。総手数800、または戦闘なし160手で引き分け。先手は人間（手前＝South）。
- **占領可能駒がなくなったとき（1.3.0）**：大将・中将・少将・大佐・中佐・少佐を「占領可能駒」とする。双方とも占領可能駒が0になった時点で、総司令部占領による勝利が不可能なので **引き分け**（「双方とも総司令部を占領できる駒がなくなりました」）。プレイヤーだけが0になった瞬間、審判が一局に一度だけ「総司令部を占領できる駒がなくなりました／投了しますか？」と確認する（CPUの勧めではない）。「続行」なら同じ対局では再表示せず、敵の動かせる駒をなくす等の勝ち筋で最後まで戦える。「投了」なら **CPUの勝ち（投了）** として正式に終局する（新規対局による破棄とは別）。CPUは投了しない。CPU側だけ0になっても通知しない（敵駒の正体の情報漏洩になるため）。
- **膠着の審判介入（1.4.0）**：同じ公開局面（全駒の番号と位置、手番）が対局中に5回現れたら、審判が一度だけ介入する（例：司令部前で守る側と攻める側が同じ往復を続け、崩した側が不利になる膠着）。介入の相手は、反復に使われている相手の駒に総司令部が近い側（盤上の距離だけで判定。駒の正体・占領できる駒かどうか・CPUの推定や評価値は一切使わない）。同じ距離なら両者。プレイヤーには「同じ局面が繰り返されています／投了するか続行するか」を一度だけ確認する（続行後の手に制限はなく、勝敗も駒の正体も示唆しない）。CPUが介入を受けた場合、以後その反復に戻る手は指さず、CPU自身の評価で次に良い合法手を指す（評価関数は変更しない）。同じ反復に対して二度は介入しない。
- **情報**：対局中、敵駒の正体は（撃破した駒も含め）公開しない。公開されるのは敵駒の番号・位置・移動（経路と飛び越し枚数）・戦闘の事実と結果（勝ち・負け・相打ち）だけ。終局直後も裏向きのまま。例外として、終局後の棋譜再現で「敵駒開示」をONにした時だけ、敵駒の正体を表示する（1.5.0〜、下記）。
- **棋譜再現と敵駒開示（1.5.0、終局後のみ）**：終局すると最終TURNを表示し、「◀◀ ◀ TURN n / N ▶ ▶▶」で1手ずつ戻る・進む（TURN 0＝初期配置。1手＝移動と戦闘・結果まで）。先頭では◀◀◀、末尾では▶▶▶が押せない。TURNごとに盤上の駒位置・自軍の損失・敵軍の損失・そのTURN時点でプレイヤーが知っていた敵駒の判明情報が同期する（未来の情報は過去のTURNに出ない）。再現中に駒をタップ／ホバーすると、そのTURN時点の観測情報だけを表示し、駒は動かせない。「敵駒開示」ON（毎局OFFで開始・保存しない・次の対局へ引き継がない）で盤上の敵駒と敵軍の損失（撃破順のまま）の正体を表示し、TURN 0ではCPUの初期配置が分かる。閲覧専用で、途中からの再開・分岐・保存・自動再生・戦闘ログ表示はない。PC：上部バーのTURN表示の位置に操作ボタン（←→キーで1手、Home／Endで先頭／末尾）。Android：縦は上部バーの2段目、横はTURN表示の位置。

## 情報隠蔽の構造

```
MilitaryShogi.Rules        公開ルール（駒種の列挙、盤グラフ、移動規則、勝敗表、配置思想）
MilitaryShogi.Observation  観測データ（PlayerView）。敵駒 EnemyPieceView には駒種のフィールドが存在しない
MilitaryShogi.Engine       AuthoritativeGameState（internal）＋ Judge ＋ ObservationBuilder。Match だけが公開
MilitaryShogi.Cpu          CpuKnowledge / CpuBrain。参照は Rules と Observation のみ（Engine を参照しない）
MilitaryShogi.Game         Unity表示。人間側の画面も人間の PlayerView だけで描く
```

- 真の駒種は `Engine` の internal な `AuthoritativeGameState` にだけ存在する。`Match` の公開APIで駒種を返すのは終局後限定の `RevealAfterGameEnd`（テスト用）だけ。
- CPUのアセンブリ（Unityのasmdefとテスト用csproj）はEngineを参照しないため、敵駒の真の種類を扱うコードはコンパイルできない。
- 駒のID・番号は初期位置の順に振るので、IDから駒種は分からない。
- 敵駒の表示オブジェクトは裏面テクスチャで生成される。戦闘演出（接近・衝突・揺れ・転倒・退場）は全駒共通で、違いは公開情報である駒の残存・消滅だけ。盤上の勝ち／負け／相打ちの文字は1.1.1で廃止し、終局結果モーダルは維持する。
- 例外は2つ。研究モードの「CPU駒の正体を表示」（1.2.0）：研究用に盤上のCPU駒の表面・思考モニター・ツールチップへ真値を出す（損失表示の敵駒は裏面のまま）。終局後の「敵駒開示」（1.5.0）：棋譜再現中にONにした時だけ盤上の敵駒と敵軍の損失の表面を出す（`GameController.PostGameReveal` は終局後しかONにならない）。対局中は対戦モードで常に無効。真値は `GameSession.ResearchTrueKind` 経由でだけ取り出し、CPU・PlayerKnownFactsには渡さない。
- 棋譜再現（1.5.0）の局面は、プレイヤーの確定したPlayerView（全駒の初期位置＋公開の着手記録）から `Observation.GameReplay.ViewAt` で再構成する（別の棋譜データを持たない）。TURN tの判明情報は、そのTURNまでの記録だけで作った `PlayerKnownFacts`。

検証（`Run-Tests.ps1` の Boundary 系）：CPUアセンブリの参照、asmdefの参照、観測型に駒種フィールドがないこと、CPUソースにリフレクション等がないこと、そして**敵の駒種だけを入れ替えた2つの対局でCPUの判断（候補・評価値・確率）がビット単位で一致すること**を確認する。

## CPUの思考方式

**1. 知識（CpuKnowledge）**：敵駒31枚それぞれについて16種の候補と確率を持つ。
- **ハード制約**（候補の除外）：観測した移動を、その駒種が本当の移動規則でできたかを移動前の盤面（公開の占有状況）で検査して除外する。1マスでも動けば地雷・軍旗を除外、3マス直進なら工兵・飛行機、横に長く動けば工兵、駒を飛び越えたり突入口を通らず帯を越えたりすれば飛行機に確定。戦闘結果は勝敗表と自軍の駒種から整合しない種類を除外する（自軍の軍旗は後ろの駒の強さで、敵の軍旗候補は後ろの敵駒の候補で判定）。初期位置による配置ルール（突入口に地雷・軍旗なし、最後列に軍旗なし）も使う。
- **ソフト証拠**（弱い重み）：初期位置の一般的な傾向、自ら攻撃してきた駒は強い駒寄り、司令部へ接近する駒は佐官以上寄り。
- **枚数制約**：31枚が標準構成であることを、（駒×種類）行列の反復比例フィッティングで満たし、各駒の周辺確率を得る。飛行機が1枚確定すれば他の駒の飛行機確率が自動的に下がる。
- 変化は駒ごとに「Turn n: 理由 ⇒ 更新後の上位候補」として記録し、直接の証拠がない駒の確率が他の駒の判明で大きく動いた場合も「再配分」として記録する。

**2. 意思決定（CpuBrain）**：全合法手について、戦闘なら勝ち・負け・相打ちの確率（信念×勝敗表）で分岐した局面を作り、静的評価の変化量で採点する。
- 評価項目：駒得（敵の価値は信念の期待値）、前進（大将〜少佐の敵司令部への接近）、司令部防衛（佐官以上らしい敵駒の、自駒の強さを考慮した経路長による危険度、迎撃できる自駒の近さ、次の手で占領される確率）、被攻撃リスク、攻撃機会、情報価値（安い駒で不確かな敵駒を突く期待エントロピー減少）、反復抑制。
- **2手読み**：全候補について相手の応手を読む。相手は自分の駒種を知っているので、敵駒ごと・移動クラスごとに信念で重み付けした応手を評価し、最も痛い応手を重み0.7で織り込む（司令部占領は負けとして扱う）。
- 評価が僅差（0.15以内）の手は Decision Seed の乱数で選ぶ。配置思想ごとに前進・防衛・リスク回避などの重みを少し変える。

**3. 配置思想（FormationGenerator）**：いのちだいじに／ガンガン行こうぜ！／じっくりいこうぜ／わなにはめろ／きどうせんだ！。駒種ごとの好む深さ・突入口への寄り・司令部への寄り（と軍旗の後ろに置く駒）を思想ごとに定め、Formation Seed のガウスノイズで揺らぎを加える。通常は Formation Seed から思想を決め、設定画面で明示指定もできる。

## Seed

| Seed | 用途 |
|---|---|
| Player Formation Seed | 人間の「おまかせ配置」（思想もこのSeedから決定） |
| CPU Formation Seed | CPUの配置思想（自動時）と初期配置 |
| CPU Decision Seed | CPUの僅差の手の選択（手番ごとに派生） |

乱数は `DeterministicRandom`（SplitMix64）で、Unity と .NET テストで同じ系列になる。同じSeed・同じ手順なら同じ配置・同じ判断を再現する。CPU配置を固定してDecision Seedだけを変えると、同じ初期局面から異なる判断を比較できる。

## 表示モード（1.1.0〜）

起動時は必ず **対戦モード**。上部の「研究モードへ」／研究モードの「対戦モードへ」、または **F2** で1クリック切替（対局中も可、1.2.0〜。設定画面からのモード切替は廃止）。
モードは表示（Presentation）だけの状態で、`GameSession`（盤面・手番・CPU Knowledge・Seed・戦闘履歴）にも乱数にも触れない。

- **対戦モード**（普通に遊ぶ画面）：上部にタイトルロゴ・TURN・手番・「あそびかた」「設定」「新規対局」、中央に3D盤、盤の左右のテーブル上に **自軍の損失**（表面・駒種順）と **敵軍の損失**（共通の裏面・撃破順）、下部に1行の状態表示。Seed・CPU評価値・推定確率は表示しない。1.1.1では敵駒ホバーにEnemy番号・位置・移動・戦闘の公開観測と、客観的に一意に確定した「判明：駒名」を表示する。
  - 対局前に **CPUの強さ（弱・中・強）** と **戦い方（かなり攻撃的〜かなり防御的）** を選ぶ（初期値：中・バランス）。Seedは内部で毎回ランダムに決まり、表示しない。
  - 自軍の駒をクリック → 緑（移動）・赤（攻撃）のマスをクリック。右クリックで選択解除。F1：あそびかた。
- **研究モード**（1.0.0のUI）：Seed入力、CPU配置思想の指定、CPUの強さ／戦い方、戦況パネル、戦闘履歴、敵駒ホバー時の観測履歴、思考モニター（意思決定・候補手・評価内訳・先読み・想定応手／敵駒の推定・推定履歴）。M：思考モニター、H：戦闘履歴、F：演出（通常／簡易）、N：番号。自軍の配置はPlayer Formation Seedの「適用／乱数」が唯一の操作（1.2.0で重複していた「おまかせ配置」ボタンを削除）。
- **あそびかた**（両モード）：勝利・敗北・引き分け（本作の対局終了ルール）、16種の駒一覧（ゲームと同じ駒テクスチャ）、選んだ駒の大きな画像・戦闘相性（勝てる／相打ち／負ける／軍旗は後ろの駒しだい）を駒画像で表示、階級駒は階級の並びの中の位置、移動は実際の盤の形の図。内容は `RuleReference`（勝敗表・移動生成と同じコード）から作る。**開いている間は対局が一時停止**する（CPUの思考結果も適用されない）。

## CPUの強さと戦い方（1.1.0）

どの設定でも敵駒の推定（CpuKnowledge）は同一で、ルール理解も同じ。違うのは「どう選ぶか」と「どのリスクを取るか」だけ。

| 強さ | 実装 |
|---|---|
| 弱 | 推定・現局面の評価は同じ。2手読みをしない。評価上位6手・評価差0.5以内から幅を持って選ぶ |
| 中 | 1.0.0のCPUと同じ（2手読み、僅差0.15以内から選択）。同じ配置思想なら1.0.0と完全に同じ手を指す |
| 強 | 2手読み。僅差の幅を0.05に狭め、情報価値（探り攻撃による推定の改善）の重みを1.25倍 |

戦い方 t（-2〜+2）は評価の重みに掛かる：前進 ×(1+0.15t)、攻撃機会 ×(1+0.12t)、司令部防衛 ×(1-0.12t)、被攻撃リスク回避 ×(1-0.12t)。
同じ t で **CPU配置思想** の選ばれやすさも変える（Formation Seedによる揺らぎは残す）：

| 戦い方 | いのちだいじに | ガンガン行こうぜ！ | じっくりいこうぜ | わなにはめろ | きどうせんだ！ |
|---|---|---|---|---|---|
| かなり攻撃的 | 0 | 45% | 15% | 0 | 40% |
| 攻撃的 | 0 | 30% | 30% | 10% | 30% |
| バランス | 15% | 15% | 40% | 15% | 15% |
| 防御的 | 30% | 0 | 30% | 30% | 10% |
| かなり防御的 | 45% | 0 | 15% | 40% | 0 |

## 1.1.1 UI/UXパッチ

- 両表示モードの敵駒ツールチップは、3D駒のRenderer Boundsの8頂点を画面へ投影して配置する。駒の周囲にUIスケール対応の余白（96論理px以上／駒の大きさの1.5倍）を取り、右側を優先し、左・上下へ回避する。ヘッダー・思考モニター等との重なりも避け、画面内へ収める。ホバー対象は細い金色枠で示す。
- プレイヤーの判明情報は `PlayerKnownFacts`（Observation層）。CPU Knowledge、確率、敵駒真値は使わない。公開の初期位置制限、移動前の占有状況、実際の移動経路・距離・飛び越し・突入口、戦闘相手の自軍駒と勝敗表から、矛盾する候補だけを除外する。軍旗の後続駒による強さも可能性として扱い、1候補なら判明、複数なら正体不明。
- 判明情報は撃破後も残り、研究モードの戦闘履歴にも反映する。自軍損失は表面・駒種順、敵軍損失は判明済みでも共通裏面・撃破順。敵の真の駒種は終局後も開示しない。
- 盤面は固定54度・FOV36度を維持し、投影の上下オフセットで上方へ配置。クリック判定も同じカメラを使う。
- 左右の損失表示は3列×最大11段、盤上駒の78%サイズ。最大31枚を画面内へ収める。
- ゲーム内の生成ロゴだけ最下段コピーを除外し、「軍人将棋／MILITARY SHOGI」を使用。UserProvidedのフル原本とアプリアイコンは変更しない。
- 初期配置UIは「CPU設定」「自軍の配置」「対局開始」を見出しと余白で分離。あそびかたの構成は維持。
- CPU・ルール・初期配置アルゴリズム・GameSessionは1.1.0から変更していない。
- 検証の詳細・限界：[1.1.1受入検証記録](Tests/ACCEPTANCE-1.1.1.md)。

## 1.2.0 の機能

- **配置プリセット**（両モードの初期配置画面）：5枠（初期名「プリセット1〜5」）。「現在の配置を保存…」で名前欄に枠の現在名が入り、そのまま保存も変更もできる（変更した名前が次回の初期値）。保存するのは各マスのPieceType（Seedではない）で、形式バージョン付きの `presets.txt`。保存時・読込時に配置規則で検証し、不正な枠は適用せず空き扱い。読み込むのは自軍配置だけで、CPUのSeed・配置・Knowledgeは変わらない。
- **ユーザーデータ**：`%USERPROFILE%\AppData\LocalLow\AF\AF-MilitaryShogi\`（`Application.persistentDataPath`）の `presets.txt`・`settings.txt`（再起動後も保持）、UI例外の `ui-errors.log`。`-dataDir <DIR>` で置き場所を変更できる（自動検証が使用）。
- **設定画面**（両モード共通、即時反映・保存）：演出 = 戦闘演出（通常／簡易）・速度（×1／×2／×4）、表示 = 敵駒の観測情報（ON／OFF、初期ON。OFFは対戦モードのツールチップだけ非表示）、サウンド = 効果音（ON／OFF）・音量（0〜100%）。CPUの強さ・戦い方は対局前のみ。
- **経過時間**：ヘッダーに「経過 18:42」（1時間以上は h:mm:ss）。対局開始で0から計測、終局で停止。設定・研究モード・思考モニター・戦闘履歴の表示中も進み、あそびかた表示中だけ止まる。結果画面にTURNと経過時間。
- **戦闘演出**：簡易＝短い接触・軽い揺れ・負けた駒（相打ちは両方）が倒れて退場。通常＝溜め→強い衝突→一拍→負けた駒が転倒・落下、勝った側も反動。文字・ネオン・爆発・パーティクルは使わない。駒種に依存しない。
- **効果音**：外部素材なし。`Tools/AudioGen/generate_sfx.py`（Python 3 + NumPy、固定Seedのモーダル合成、バイト単位で再現）で木の乾いた音を生成：選択「コッ」、着手「コトッ」（3種）、衝突「カッ」（2種）、転倒「カタン」、終局（拍子木風）。BGMなし。音は視覚イベントと同じフレームで開始し、転倒音は打撃成分が駒の着地と一致するよう開始時刻をずらす（×1／×2／×4とも）。
- **盤面レイアウト**：盤＋左右の損失置き場（各31枚分を最初から確保）を1つの視覚グループとして、プレイ領域の中央へ投影オフセットで配置（カメラ角度・パースは固定、固定px調整なし）。研究モードは表示中の研究UIを除いた領域で計算。損失置き場は盤上駒の86%・3列×11段、見出しと1段目の間に余白。自軍・敵軍の置き場は高さ・向き・スケール・影・卓面距離を共通化し、違うのは面（自軍は表・敵軍は裏）と並び順だけ。対戦モードと、研究モードで思考モニターを閉じている時に表示し、モニター表示中は隠す。
- **UIの異常対策**：1.1.1の「研究モード初期配置で画面が暗くなりボタンが効かない」事象は、思考モニターで過去TURNを表示したまま新規対局した時に、報告のない初期配置で `DrawBeliefs` が毎フレーム `NullReferenceException` を出し、IMGUIの描画が途中で打ち切られていたことが原因（ユーザー環境の Player-prev.log で41,262件）。表示中のTURNを初期配置でリセットし、報告がなければ最新推定を表示するよう修正。加えて、全IMGUIを `UiGuard` で包んで例外時に入力状態を復旧・記録し、`Presentation` のウォッチドッグであそびかたと一時停止・timeScaleの整合を毎フレーム保証する。

## 1.3.0 の機能

## Android版（1.3.0）

PC版の **対戦モードだけ** をスマートフォンで遊べるようにしたもの。研究モード（思考モニター・Seed操作・CPU真値表示・研究用戦闘履歴・研究用ショートカット）は搭載しない。ゲーム本体（Rules・Engine・Observation・CPU・GameSession・GameController・プリセット・設定・効果音）はPC版と同じコードで、画面（Presentation）だけAndroid用の `MobileUi`。

- **操作**：自軍の駒をタップ → 移動先をタップ（PCのクリック操作と同じ。ドラッグは使わない）。移動先を狙ったタップが外れて移動できないマスや盤上のマス以外に当たっても、選択は解除されない（1.4.1〜。盤外のタップで解除、別の自軍駒で切替、近くの移動先への自動補正はしない）。敵駒をタップすると、その駒を枠で示して公開観測（Enemy番号・位置・移動・戦闘・判明した駒種）を表示。別の敵駒で切替、駒のない所をタップで閉じる。設定「敵駒の観測情報」OFFでは表示しない。CPU内部の推定や真値は表示しない。
- **画面の向き**：縦・横とも対応し、回転しても対局（GameSession・盤面・手番・CPU Knowledge・乱数・経過時間・履歴・プリセット）はそのまま。表示だけを組み直す。
  - 縦：上＝タイトル・TURN・手番・経過、敵軍の損失（裏面・撃破順、12枚×3段の小さな駒画像）、盤、自軍の損失（表面・駒種順）、下＝状態・あそびかた・設定・新規対局。初期配置では下半分がCPU設定・自軍の配置・プリセット・対局開始のシート（指でスクロール、「盤を広く表示」でたためる）。
  - 横：PC版に近い構成（上のバー、盤の左右に3Dの損失置き場）。初期配置のシートは右側。
- **大きさと安全領域**：UIの単位はdp（dpi/160）で、ボタンは高さ48dp以上。すべて `Screen.safeArea`（ノッチ・パンチホール・ナビゲーション領域）の内側に配置。
- **Modal**：設定・あそびかた・新規対局の確認・審判の確認・終局結果はPC版と同じ `ModalInput` で、背後の盤面・UIへタップが届かない。Androidの戻るキーは最前面のModalを閉じる。
- **バックグラウンド**：ホーム・別アプリ・画面OFF・フォーカス喪失で一時停止（CPUの手番、戦闘演出、経過時間も停止）。戻ると同じ対局から再開。OSによるプロセス終了後の対局復元は未対応。
- **プリセット**：PCと同じ5枠。名前はAndroidのソフトウェアキーボードで入力（保存を始めるとシートが名前欄までスクロール）。
- **効果音**：PCと同じ生成WAV・ON/OFF・音量。AudioListenerはメインカメラの1つだけ。
- **文字**：端末のCJKフォント（Noto Sans CJK等）を使用し、フォントファイルは同梱しない。
- **APK**：`Build-Android.ps1` で `bin/Android/Release-<Version>/AF-MilitaryShogi-<Version>.apk`（ARM64/IL2CPP Release、デバッグ不可、シンボルなし、専用のローカルRelease鍵で署名）。自分の端末へインストールして遊ぶためのもので、GitHub Releases・`Distribution/` 等で **一般配布しない**。

## 駒の文字のフォントとテクスチャ生成

- 駒の文字（16種の駒名）と盤の「総司令部」には **昭和書体「闘龍」（KSO闘龍）** を使用している（使用許諾：https://designpocket.jp/font/detail/23984 ）。
- 配布版の駒テクスチャは、正規ライセンスのKSO闘龍で画像化して生成済みで、PNGとしてコミットしてある（`Assets/Generated/Resources/Textures/`）。
- **フォント本体はリポジトリにも配布物（Windows ZIP・Android APK）にも含まれない。** `.gitignore` でフォントファイル（otf/ttf/ttc/woff/woff2/eot）を除外している。
- **ゲームのビルド・実行にKSO闘龍は不要。** 生成済みテクスチャがコミットされているので、cloneしてそのままビルドできる。ビルドやZIP作成はテクスチャ生成スクリプトを実行しない。
- テクスチャ生成スクリプト `Tools/TextureGen/generate_textures.py` を再実行した場合、KSO闘龍がOSにインストールされていればそれを使う。なければ（その旨を表示して）OSの日本語フォント（Yu Gothic、Meiryo、Noto Sans CJK等）で最後まで生成する。代替フォントの生成物は配布版と文字のデザインが異なる。`--out <フォルダー>` で出力先を分けると、コミット済みのテクスチャを変えずに試せる。
- 生成記録（入力と出力のハッシュ、要求したフォント・実際に使ったフォント・代替したか）は `Generated/texture_generation_manifest.json`。

## ビルドとテスト

```powershell
./Run-Tests.ps1            # 全テスト（約4分）。-Quick で短縮
./Build-Windows.ps1        # bin/Release-<Version>/AF-MilitaryShogi.exe
./Run-AutoTest.ps1         # ビルドしたEXEで自動対局して検証（2回実行して比較）、Builds/AutoTest/<日時>/ に結果
./Build-Android.ps1        # bin/Android/Release-<Version>/AF-MilitaryShogi-<Version>.apk（署名・検証つき）
./Test-Android.ps1         # 接続した端末へAPKを入れ、実タップ・回転・ホーム・Modal・プリセット・効果音を検証
./Package-Windows.ps1      # 配布候補ZIP（Builds/Package/）。公開準備で Prepare-Release.ps1 が Distribution/ へ
```

- `Tests/` の .NET 9 プロジェクトは `Assets/Scripts/{Rules,Observation,Engine,Cpu}` をUnityのasmdefと同じ参照関係でコンパイルする。
- EXEの自動検証（`-autotest`）：起動時が対戦モード、タイトルロゴが上部バー内に表示、16種の駒テクスチャ、全66ノードのマウス選択、クリックによる配置編集、人間側の着手をクリック処理経由で行って終局まで進行、対戦→研究→対戦でセッションの指紋と `UnityEngine.Random.state` が不変、あそびかた表示中に対局が進まない、損失表示（枚数一致・自軍は駒種順・敵は撃破順で位置は撃破番号だけで決まり全て裏面）、毎フレーム全ての敵駒（盤上・損失表示）が裏面のみ、両モードとあそびかたのスクリーンショット。
- 1.2.0で追加した自動検証：プリセット（初期名・名前の引継ぎ・配置の完全一致・両モード・不正データの拒否・CPU不変・再起動後の保持）、UI状態遷移ストレステスト（初期配置と対局中に各160回のランダム操作：モード切替・あそびかた・設定・モニター・履歴・演出・速度・番号・正体表示・過去TURN表示・Seed・プリセット・新規対局。各操作後にUI例外なし、一時停止とあそびかたの一致、現モードのUIだけが描画、モーダルなしで盤中央を覆うUIがない、対局中は指紋と乱数状態が不変）、1.1.1事象の再現シナリオ、経過時間の規則、通常／簡易×速度3種での効果音同期、効果音ON/OFF・音量・設定の保存、損失置き場の共通Transform・影・見出し余白・78%以上・31枚収まり、視覚グループの中央配置（4解像度×対戦／研究モニターON・OFF）、ツールチップの観測情報OFFと研究真値表示・解除。
- Modal入力の実クリック確認：`AF-MilitaryShogi.exe -modalprobe <報告ファイル>`。Windowsのカーソルを実際に動かしてクリックし、設定・あそびかた表示中に背後のUI・盤面が反応しないこと、閉じるクリックが背後へ届かないこと、時計の進み方を確認する（約40秒、実行中はマウスに触れない。1.2.2〜）。
- 効果音の実出力の確認：`AF-MilitaryShogi.exe -audioprobe <報告ファイル>`。AudioListener・AudioSource・クリップの状態と、Unityの出力ミックス（`AudioListener.GetOutputData`）のピークを直接再生・駒クリック経由・効果音OFF・音量違いで測定する（1.2.1〜）。
- `Run-AutoTest.ps1` は新しいユーザーデータフォルダーで、同じSeedの通常実行と `-toggleModes -expectPersisted`（毎手モードを切り替え、前回実行で保存したプリセット・音量を確認）を行い、終局時の指紋が一致することと、EXEのアイコンが生成したアプリアイコンであることを確認する。
